# 穿搭管理器 · 二改版

基于 **温水 & 克洛宜** 的 Outfit Manager 二次修改与维护，用于在酒馆中保存穿搭、单品和套装，并让当前聊天使用已选择的衣服。

**前端 2.4.11 · 配套后端 2.2.1。** 本包为二改版本，保留原作署名。仓库和安装包保留开发测试，文档集中在本 README，不包含个人衣柜数据。

## 主要功能

- **聊天独立预设**：每段聊天记住自己的衣柜、当前穿着与候选；同一角色的不同聊天也独立保存。
- **穿搭与单品**：分类、搜索、收藏、套装关联，分类栏旁的单按钮切换，不额外增加主界面行数。
- **固定／衣柜模式**：固定模式点图换上、再点取消；衣柜模式点图增减候选，随正常聊天生成选衣。
- **标签与描述**：本地按名称、分类及描述推断时代、风格和用途；可选图片识别。默认穿搭描述 150～200 字，保留自定义提示词。
- **便携衣柜备份**：导入导出穿搭、单品、分类、套装及图片，支持大文件、同名不同衣服和保存失败保护。
- **运行错误日志**：自动保留穿搭自身的异常与已接入的功能失败，区分已确认情况、可能原因与处理建议；可暂停、清空和导出脱敏日志。
- **兼容性检查**：离线请求读回、点击传递、样式对照和合成注入自检，按证据显示干扰来源；支持停用前后对照及 10 分钟复现记录。
- **五套主题**：保留各自的按钮、轮廓与装饰，兼顾手机显示和静止状态下的性能。

## 前端安装与更新

1. 从当前版本导出衣柜备份，保留原文件。
2. 在酒馆扩展管理中安装本仓库：`https://github.com/TokkiO-O/Outfit-Manager.git`。已有该扩展时更新同一副本。
3. 按原来安装扩展的方式更新本包。普通 SillyTavern 的前端文件应放在现有扩展目录中，manifest.json、index.js、src 直接位于该目录下，不要再套一层同名目录。
4. 保留原有数据，避免同时启用两个 Outfit Manager 副本。完整重启宿主或刷新酒馆，确认显示 v2.4.11。

本版在 TauriTavern 中使用本地存储。不要把配套服务端 ZIP 当作 TauriTavern 前端扩展安装。普通 SillyTavern 可按配套后端仓库 README 选装后端。

## 常用操作

| 入口 | 用法 |
| --- | --- |
| 分类栏旁的单品／穿搭按钮 | 点击切换浏览对象；小图标按钮点击往返切换，悬停或无障碍名称提示目标 |
| 底部预设 | 为当前聊天选一次衣柜，之后回到这段聊天自动恢复；编辑内容自动保存 |
| 多选 | 先勾选衣服或单品，再打开批量操作；分类与 AI 调用先核对范围 |
| 更多 → 本次穿搭 | 查看当前穿着、模式、候选、临时单品与剧情换装设置 |
| 更多 → 场景推荐／搭配建议 | 通过本地文字规则，按场景、风格与季节查找衣服 |
| 更多 → 全部套装／穿着历史 | 查看已关联的搭配，或回看本聊天实际穿过的衣服 |
| 更多 → 标签词库／操作撤销／数据体检 | 整理标签、恢复修改和检查衣柜引用 |
| 更多 → 设置 | 配置发送内容、外观、识图接口、分类与数据；性能自检位于调试页 |

切换预设不复制或覆盖另一个衣柜。同一聊天切走又切回某个预设，其中原来的选择会保留，发送时只使用当前预设。预设删除前会确认，旧聊天缺少有效归属信息时需要重新选择一次。

本地标签不会读取图片。已有自动标签可在“标签”页重新整理；默认保护手工标签。少量缺少服装信息的记录仍需补充名称或描述，不用泛用的拍照、节庆或日常标签凑数量。

## API 与数据范围

本地标签、预设管理、搜索、场景推荐、搭配建议、套装查看、历史、撤销、体检、性能自检及兼容性检查不调用生成 API。

衣柜模式选衣随正常聊天回复完成，不额外请求识图接口；候选资料会增加正常生成的输入用量。固定或锁定的衣服不会自动换装。

图片描述、图片分类和图片标签需要在“设置 → 发送与提示词”配置支持图片的接口与模型，保留模型列表和手动填写。执行前会核对本次范围与用量，可停止后续请求。

衣柜分享文件不携带 API、主题、提示词或聊天状态。后端私有 data 目录与可分享的衣柜导出不是同一种文件，不要把个人数据目录放进公开安装包。

## 冲突检测与错误原因

入口为“设置 → 调试”。兼容性检查会走离线请求链、测试点击传递、检查按钮遮挡及样式，并用合成衣服验证筛选、聊天隔离、预算和内容写入，不调用模型 API 或修改真实衣柜。完整离线读回还会观察穿搭处理器内外层的转接组件；浏览器策略导致的失败会保留为线索，不直接认定扩展有问题。

结果按组件显示“检测到测试干扰、关联线索、本次透传正常、本次未覆盖”。点击阻断、外层探针报错和可验证的外部样式影响会标明文件位置；样式对照在同一次同步操作中临时移除声明并立即还原。调用栈中的扩展名、覆盖层的声明归属和仅匹配的样式只能提供线索。检测范围不覆盖所有真实手势、接口路径、跨域样式和未执行功能，不能把未覆盖当成无冲突。

找不到具体来源时，在异常状态保存对照起点，保留聊天后手动停用一个怀疑扩展并完整刷新，再用相同主题、窗口和版本检测。工具列出加载组件与测试结果的变化；只有一个组件不再加载且异常恢复时会提示对照线索，仍需重新启用复测。工具不会替你停用扩展、刷新或改设置。

运行错误日志默认开启，保留最近 7 天、最多 200 条，同类同位置合并，频繁报错限流。除时间、次数、分类、HTTP 状态、版本和文件行列外，还会说明直接事实、可能根因及处理步骤，例如区分接口 429、接口额度不足标记、本地存储配额不足和对象未初始化。关联调用位置不等于根因；证据不够时会明确写无法唯一确定。支持筛选、暂停、清空和导出；启动失败的恢复窗口也能查看日志。

日志不保存原始报错正文、函数名、完整地址、API 配置或衣柜与聊天内容。从本版启动后开始记录，无法还原过去的错误；未接入的已捕获错误、缺少穿搭位置的 Promise 异常以及浏览器崩溃可能无法完整记录。存储受限时当前页面仍可查看／导出。兼容性报告附带最近 20 条脱敏日志、原因说明及对照结果。
